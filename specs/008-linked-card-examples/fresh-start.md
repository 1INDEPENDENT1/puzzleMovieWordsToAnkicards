# Первоначальное построение учебной коллекции

**Date**: 2026-11-10. Заменяет прежний план переноса старых карточек по прямому решению пользователя. Это инструкция для будущей реализации; очистка данных в текущей работе не выполнялась.

## Границы

Новая коллекция строится с нуля: прежние карточки, ответы, расписания и ручные правки не переносятся. Не нужны таблицы архивов, объединение карточек, выбор расписания донора или интерфейс разрешения прежних правок. Новые карточки создаются из свежего профиля со стандартным начальным состоянием scheduler.

Учетные записи users, PuzzleMovies session tokens, export_jobs и файлы TSV не относятся к пересоздаваемой учебной коллекции. Новые snapshots создаются только для новых экспортов; старые файлы не используются для восстановления структурированных учебных данных.

## Однократная подготовка при реализации

1. Определить точную целевую базу из конфигурации запуска. Остановить приложение и закрыть доступ к учебным операциям на время подготовки.
2. Пересоздать только review_attempts и review_cards с зависимыми учебными ограничениями, в порядке зависимостей. Если проверку новой модели повторяют, аналогично очистить только её каталог, примеры, links и snapshots. Не использовать глобальный DROP SCHEMA или очистку users/export_jobs; не применять CASCADE без проверенного перечня зависимостей.
3. Запустить приложение с новой моделью. JPA создаёт новые пустые mapped tables; штатный Spring SQL initializer после Hibernate добавляет/проверяет составные ограничения новой схемы. Использовать defer-datasource-initialization=true, сохраняя PostgreSQL и текущий @@ separator. Инициализация идемпотентна и не содержит DELETE/TRUNCATE/DROP для рабочих учебных данных.
4. Выполнить свежий WORDS/COMBINED export; после прежних проверок предупреждений нажать создание карточек. Получить одну карточку на слово, связанные примеры и пустую историю.

На подтверждённой целевой базе открыть `psql` и проверить вывод `\conninfo` перед выполнением. Для первого перехода использовать следующую транзакцию.

```sql
BEGIN;
DROP TABLE IF EXISTS review_attempts, review_cards;
COMMIT;
```

Транзакция удаляет прежние карточки и попытки целиком. Если неожиданная зависимость не даёт удалить таблицу, PostgreSQL откатывает операцию. Проверить зависимость отдельно до нового запуска. Старая заполненная учебная схема требует этого явного однократного шага. Нормальный startup и POST импорта данные не очищают.

## Последующая работа

После первоначального построения действуют обычные гарантии сохранности: restart и повторный импорт не очищают каталог, ответы, расписание или ручные overrides. Новые примеры добавляются к существующей карточке без создания ещё одной карточки слова.

## Критерии проверки

- Чистая PostgreSQL создаёт необходимые таблицы и ограничения; повторный старт ничего не очищает.
- users, session tokens, export_jobs и TSV не затрагиваются подготовкой учебной коллекции.
- Первый свежий импорт создаёт карточки со state NEW, reviewCount=0 и без ReviewAttempt.
- После ответа и ручной правки повторный импорт сохраняет новые ответы, расписание и правки.
- Ни одна ветвь приложения не переносит старую историю, не пытается разделять старые смешанные переводы и не создаёт архивы/интерфейс разрешения прежних правок.
