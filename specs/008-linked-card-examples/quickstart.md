# Quickstart: Проверка связанных карточек и всех примеров

**Date**: 2026-11-10. Сценарии для будущей реализации. На этапе планирования они не выполнялись и не считаются пройденными.

## Предварительные условия

- Java 21 и Maven; локально разрешённая зависимость org.drugov:lingua-core:0.1.0.
- Отдельная тестовая PostgreSQL или Docker для Testcontainers; H2 не использовать.
- Пустая тестовая база для новой учебной коллекции. Рабочую базу не менять при проверке.
- Два тестовых пользователя и структурированные fixtures без cookie, пароля или реальных персональных данных. words.html/phrases.html из рабочей папки не публиковать как fixtures без обезличивания.
- [Модель](data-model.md), [первоначальное построение](fresh-start.md), [контракты](contracts/http-and-ui.md) служат эталоном форматов и ожидаемого поведения.

## Запуск

Из корня репозитория:

```powershell
mvn test
mvn spring-boot:run
```

Настройки соединения задаются существующими spring.datasource overrides, без записи секретов в документы/логи. Тесты PostgreSQL, пропущенные из-за недоступной базы, явно указать в отчёте; они не доказывают работоспособность новой схемы. Открыть приложение через /login; для автоматизированных web-тестов использовать существующие session fixtures.

После реализации запускать целевые matching/import/schema/repository/controller тесты, затем весь mvn test. Новые тесты должны проверять требования и сохранность, а не только наличие строк в исходниках. Браузерную проверку JS нельзя заменить static asset smoke тестами.

## 1. Сопоставление и сохранность источников — SC-001, SC-002

Подготовить контрольный набор, где expected associations заданы независимо от реализации:

| Данные | Ожидание |
| --- | --- |
| maintain / maintained | Соответствие с сохранением исходного текста |
| to mince / to run | Разные единицы; общий to не создаёт связи |
| a doofus / the doofus in the room | Совпадение по изучаемому слову, не по артиклю |
| give up / give up, give it up, give a good thing up | Принять разрывы 0, 1, 3 |
| give up / give a very good thing up | Отклонить разрыв 4 |
| give up / up … give, только give, give. Up | Отклонить обратный порядок, неполное выражение, разные предложения |
| Выражение из трёх частей с разрывами 3 и 3 | Принять: предел не суммарный |
| Повторные токены и позднее подходящее вхождение | Найти полную допустимую цепочку; не только первое вхождение |
| he / the | Нет совпадения подстроки |
| Одинаковая фраза из двух фильмов | Оба источника доступны |
| Слово с 0, 1, 2, 5, 100 примерами | Все примеры доступны, одна карточка слова |

Дополнить эталон сокращениями/числами/кавычками на границах предложений и токенами с апострофами. Зафиксировать поведение адаптера предложения и lingua tokenizer, не подменять ожидаемый результат выводом проверяемого matcher. Сохранять слова без переводов, неизвестных лемм и фильмов.

## 2. Импорт и restart — SC-004

1. Завершить WORDS/COMBINED export с пятью примерами. Перезапустить приложение до POST создания карточек. Ожидание: import snapshot доступен; создание карточек не требует process cache.
2. Создать карточки, открыть /cards: одна строка слова, exampleCount=5. Повторить POST того же job, затем новый идентичный export/import: количество карточек, примеров и одинаковых links не меняется.
3. Перезапустить после импорта: все данные, источники и links доступны, примеры листаются.
4. Импортировать PHRASES без слов: ноль самостоятельных карточек фраз, примеры сохранены. Затем импортировать слово: прежний пример связывается без повторного скачивания его текста.
5. Сохранить встроенный пример WORD и пример без пары; убедиться, что оба не потеряны.
6. Повторить PARTIAL из 007: до просмотра предупреждения POST возвращает прежний 303; после просмотра доступный материал импортируется. Старые записи не удаляются из-за отсутствия в частичном наборе.
7. Сымитировать ошибку сохранения snapshot/публикации: completed не показывается без обязательных данных, транзакция не оставляет частичных links или published_at. Проверить concurrent imports одного владельца.
8. На наборе около 1500 слов/800 фраз записать время/объём, число запросов и отсутствие N+1. Не объявлять неподтверждённый SLA.

## 3. Переводы и окно — SC-003, SC-007

1. В /reviews открыть «Примеры» до main reveal. Видны только original/film/i из N; перевод disabled. Попытка POST перевода с тем же presentation до reveal даёт 409, без attempts.
2. Раскрыть основную карточку: показывается только перевод слова. Отдельно нажать «Перевод» примера: появляется его русский текст.
3. Перелистнуть и вернуться: каждый раз перевод скрыт. Закрыть Escape и открыть снова: main reveal сохранён в текущем показе, перевод примера скрыт, фокус вернулся к trigger.
4. Перейти к другой карточке, обновить страницу, открыть вторую вкладку: новые presentation не наследуют разрешение первой. Старый/истёкший presentation не выдаёт перевод.
5. Задержать ответ сервера и сменить пример/карточку: поздний результат не появляется в новом контексте.
6. Пройти 100 примеров, включая границу страниц 25/26: точный total, ни скрытого cap, ни повторов/пропусков. Для N=0/1 корректны пустое состояние и границы навигации.
7. Проверить пустые переводы и фильм, клавиатуру, мобильную ширину, reduced-motion, ошибки сети и возврат фокуса. Ни одно действие примеров не меняет due/history/statistics.

Исполняемая проверка запускает headless Chrome или Edge из `ReviewExamplesBrowserTest`. Нужны Node.js 22+ и путь к Chromium-браузеру. В PowerShell:

```powershell
$env:REVIEW_BROWSER = 'C:/Program Files/Google/Chrome/Application/chrome.exe'
mvn '-Dtest=ReviewExamplesBrowserTest' test
```

Тест рендерит реальные шаблоны Thymeleaf, запускает JS и CSS в браузере и подставляет контролируемые HTTP-ответы. Он проверяет 0 и 100 примеров, границы страниц, отдельное раскрытие, запоздалый ответ, повторное открытие, Escape и возврат фокуса, мобильную ширину, reduced motion и сохранение выбранного примера с версией. Без переменной `REVIEW_BROWSER` Maven пропускает этот тест.

## 4. Чистое построение и последующая сохранность — SC-005

1. Создать новую учебную схему на отдельной PostgreSQL по fresh-start.md. Проверить FK/UNIQUE и повторный startup: данные не очищаются.
2. Выполнить свежий импорт. На слово ровно одна карточка, state NEW, reviewCount=0, ответов нет. Старая история или правки не восстанавливаются из TSV/HTML.
3. Ответить на карточку и изменить её перевод/пример. Повторить импорт и restart: новый ответ, ручные overrides и расписание сохраняются.
4. Проверить однократную подготовку на изолированной базе с контрольными users/session tokens/export_jobs: эти данные и файлы экспорта не затронуты. Не включать сброс учебных таблиц в startup или импорт.
5. Проверить конкурентные импорт/answer/edit и stale versions: ответы не теряются, устаревшая запись получает 409, повторный импорт не создаёт дублей.
6. В коде нет архивной модели, объединения истории, выбора расписания прежней карточки или интерфейса старых правок. Предыдущие schema migration tests заменены тестами чистой схемы и идемпотентного старта.

## 5. Изоляция и редактирование — SC-006

Два пользователя имеют одинаковый original, но разные переводы/фильмы. Проверить /cards, /reviews, examples, reveal и все PATCH/POST с чужими UUID. Ожидаются 404 и отсутствие изменений. Прямая попытка SQL cross-owner link отклоняется FK.

Изменить пример из карточки одного слова: виден его override только в этом контексте; другой связанный со source example термин остаётся прежним. Проверить сохранение override после импорта. Изменить main original/translation: source identity и расписание прежние, links пересчитаны в пределах владельца. Форма без выбранного exampleId не меняет произвольный пример.

## 6. Регрессия экспорта и отчёт

Проверить WORDS, PHRASES, COMBINED, TSV ровно в две колонки, escaping и скачивание, явные предупреждения rejected/counter discrepancy из 007. In-app имеет все примеры, TSV может сохранять прежний display cap как проекцию. Проверки полноты и логин не ослаблены.

В отчёте реализации перечислить команды и результаты, реально выполненные PostgreSQL/browser сценарии, результаты первого импорта и сохранность новых данных после повторного импорта/restart. Перенос старых карточек не является критерием готовности. Очистку рабочей базы эта проверка не выполняет.


## Результаты реализации 2026-11-11

- Java 21.0.11, Maven из IntelliJ IDEA, отдельный кластер PostgreSQL 17 и headless Chrome. PostgreSQL запускался локально в отдельном каталоге данных.
- Финальный Maven-прогон с `review.test.jdbc-url`, `linked.test.jdbc-url` и `REVIEW_BROWSER`: 172 теста, 0 ошибок, 0 падений и 0 пропусков.
- PostgreSQL и MVC подтвердили чистую схему, ограничения владельца, два одновременных импорта, 100 примеров у одной карточки, переход 25/26, запрет преждевременного раскрытия и сохранность импорта, ручного перевода и ответа после двух запусков контекста.
- Chrome с приложением, отдельной PostgreSQL и контролируемым источником прошёл от входа и импорта до просмотра, отдельного перевода, ручной правки и записи одного ответа. Отдельный браузерный тест проверил 0 и 100 примеров, клавиатуру и задержанные HTTP-ответы.
- На изолированной копии тестовой базы проверено однократное удаление только `review_attempts` и `review_cards`. Сохранились по четыре записи пользователей, токенов и заданий экспорта.
- На синтетическом наборе из 1500 слов и 800 фраз сопоставление занимало 151–170 мс в трёх запусках. Все 800 ожидаемых связей найдены. Пагинация примеров загружает источники вместе со связями.
- Запятая остаётся внутри предложения и не увеличивает разрыв. Используется первая нормальная форма из lingua-core. В частности, библиотека выдаёт `go` для `went` и `running` для `running`, поэтому последнее не всегда совпадает с `run`.
