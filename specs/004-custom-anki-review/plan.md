# Implementation Plan: Custom Anki-Style Review Cards

**Branch**: `codex/004-custom-anki-review` | **Date**: 2026-06-15 | **Spec**: [spec.md](C:/Users/George/javaProjects/puzzleMovieWordsToAnkicards/specs/004-custom-anki-review/spec.md)

## Summary

Add a first-class in-app review mode that studies vocabulary records generated by the existing export flow without parsing arbitrary Anki templates. The feature introduces owned review-card persistence, review attempts, binary scheduling with "I know" and "I don't know", a responsive front/back review UI, lookup actions inspired by the user's current Anki card, and animated answer transitions with reduced-motion support. The existing Anki-ready TSV export remains available; review becomes an additional study path.

## Technical Context

**Language/Version**: Java 17  
**Primary Dependencies**: Spring Boot 3.2.x, Spring MVC, Thymeleaf, Spring Data JPA, PostgreSQL JDBC driver, Java HttpClient, Jsoup, org.drugov:lingua-core 0.1.0, JUnit 5, Mockito, Testcontainers PostgreSQL  
**Storage**: PostgreSQL for users/session tokens/export jobs/review cards/review attempts/scheduling state; filesystem remains only for generated export files  
**Testing**: JUnit 5 unit tests for card creation, duplicate keys, scheduling transitions, and lookup URL generation; Spring MVC tests for review pages and answer endpoints; Testcontainers PostgreSQL retained for persistence integration where needed  
**Target Platform**: Local JVM web application started via Maven or executable JAR  
**Project Type**: Single Spring Boot web application  
**Performance Goals**: Review session opens and displays the first due card in under 10 seconds; a 50-card due queue completes without reloads or lost answers; scheduling and due-card queries remain responsive for modest local vocabulary collections  
**Constraints**: Existing export/download behavior must remain intact; first release uses exactly two scheduling buttons; arbitrary Anki template import/parsing is out of scope; external lookup pages must not block review; reduced-motion users must get a clear non-sweeping transition  
**Scale/Scope**: Single-user/local usage with modest vocabulary collections; multiple browser tabs should not corrupt review state; session queue size can be capped to a practical page/session limit

## Phase 0: Research

Research is captured in [research.md](C:/Users/George/javaProjects/puzzleMovieWordsToAnkicards/specs/004-custom-anki-review/research.md). Key decisions:

- Use a binary Anki-like scheduler for the first release instead of implementing full FSRS immediately.
- Keep learning/relearning retries short and same-day.
- Store review attempts separately from current scheduling state.
- Build lookup URLs from card fields on demand.
- Use CSS transitions for sweep animation with `prefers-reduced-motion` fallback.
